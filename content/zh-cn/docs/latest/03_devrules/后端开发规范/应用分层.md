本章约束业务代码、模型和依赖方向。经典三层可作为基础组织方式；复杂业务可以进一步划分应用服务与领域能力，但需保持清晰边界。原有架构、工程目录与对象传递图作为本章的共同参考。

## 分层与依赖方向

`Controller → Service → Mapper → 数据库` 是常见业务调用方向。依赖由接口适配向业务、持久化方向组织，不让 Mapper 反向调用 Controller，也不让公共契约依赖服务实现。

### 各层职责

| 层次 | 必须承担的职责 | 必须避免 |
| --- | --- | --- |
| Controller | 接收请求、结构校验、调用业务接口、返回结果 | 直接访问 Mapper，堆叠事务和复杂业务规则 |
| Service | 业务状态、授权、事务和操作编排 | 依赖前端约定保证数据安全，跨服务直接访问表 |
| Mapper | 参数化查询和持久化 | 拼接不可信 SQL，忽略数据范围及结果规模 |
| Converter | 字段映射与模型转换 | 隐藏远程调用、权限决策、数据库写入 |

Controller 返回业务结果，统一响应包装交给 Web Starter。Service 明确本地事务边界，查询与写入分别落实操作权限；多表一致性由事务保护，多服务一致性另行设计。

## 模型对象约定

![各层模型对象传递关系](../images/layer-model.png)

| 模型 | 命名示例 | 约束 |
| --- | --- | --- |
| Query | `OrderPageQuery` | 查询条件、分页和排序；同一语义可贯穿服务内各层 |
| Form | `OrderCreateForm` | 按写入场景暴露允许字段，声明输入校验 |
| DTO | `OrderDTO` | 明确定义的传输契约，不作为所有对象的默认后缀 |
| VO | `OrderDetailVO` | 面向调用方的结果，只暴露契约字段；此处指 View Object |
| BO | `OrderSummaryBO` | 联表、组合或计算结果，默认留在服务内部 |
| Entity | `Order` | 表映射与持久化属性，不直接作为新增 REST/Feign 契约 |

查询结果通常由 Entity/BO 转为 VO；写入 Form/DTO 经 Service 校验后转换为持久化模型。转换优先使用 MapStruct/MapStruct Plus，并明确忽略或在服务端设置主键、租户、拥有者和审计字段。

同一语义的模型允许复用，不必为了补齐后缀在每一层创建同字段副本。Query、Form、VO 可以是稳定的 API 契约；也不能因字段相同就把数据库 Entity 直接暴露给调用方。

## 跨服务边界

![微服务与 OpenAPI 的模型传递](../images/model2.png)

- 必须将共享接口及必要模型放入所属服务的 `*-api` 模块。调用方只依赖契约，不依赖对方 Service、Mapper、Entity 或资源文件。
- BFF 面向页面编排接口，核心业务状态与事务由业务服务维护。避免 BFF 和 Service 分别实现一套相同业务规则。
- 调用其他服务时按对方 Query/Form/DTO 组织入参；返回后存在聚合、裁剪或语义差异时，再转换为本方 VO。
- OpenAPI 处理对外契约；Thirdparty 适配第三方协议和模型，第三方错误、SDK 类型及凭据不扩散到核心业务。

跨服务共享契约不代表共享数据库。API 模块不单独运行，也不注册资源服务器、数据库连接或运行时可观测性组件。

## 校验与权限放置

Controller 校验格式与字段约束，Service 校验业务状态、身份和资源权限，Mapper 查询落实数据范围；数据库约束保护并发下的不变量。任一层的校验不能替代其他边界。

客户端传入的 `tenantId`、拥有者 ID 或角色仅是输入，必须与可信身份和授权结果核对。Converter 不承担认证授权，字段复制不会自动证明调用方有权设置这些值。

## 检查与相关指引

评审时检查：依赖是否单向、契约是否泄漏内部类型、事务是否在业务边界、模型是否过度复制、查询是否落实数据权限。
