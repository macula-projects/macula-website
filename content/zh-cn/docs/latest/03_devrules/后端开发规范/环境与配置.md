配置文件描述应用的结构与接入方式，配置中心管理共享环境的运行值，部署环境提供实例位置和敏感材料。本章说明三者的分工、生效规则与发布要求；Samples 的具体目录和端口仍见[示例配置](/docs/latest/04_devmanual/模块说明/#示例配置)。

## 配置归属

| 位置 | 放什么 | 避免什么 |
| --- | --- | --- |
| 仓库公共配置 | 应用名、profile 分组、配置导入、路由结构、组件默认行为 | 生产密码、个人机器地址、重复维护全部环境值 |
| `local` / `docker` | 本机开发默认值、容器 DNS 与端口差异 | 指向生产实例，混用宿主机映射端口与容器端口 |
| 共享环境配置中心 | 业务开关、连接池、超时、平台 endpoint、可观测性等环境值 | 放入“连接配置中心本身所必需”的唯一连接信息 |
| 环境变量或密钥设施 | 激活环境、配置中心入口、实例差异、凭据与密钥 | 把秘密写进镜像、源码或前端可见配置 |

同一个配置键应有明确的维护位置。允许覆盖是框架能力，不代表应让同一个值在 YAML、Nacos、Compose、启动参数中各维护一份。

## 配置示例

下面给出一个业务服务的组织示意，使用 Spring Boot Config Data 与 Nacos；按本项目实际 Starter 和部署值调整。代码先集中展示，关键项在后文解释。这里的 `order-service` 是通用示例名，不是 Samples 的新增模块。

### 仓库中的 application.yml

```yaml
spring:
  application:
    name: order-service
  # 本例未指定环境时进入 local；共享环境由部署显式设置。
  profiles:
    active: ${APP_PROFILE:local}
    group:
      docker: local
  config:
    import:
      - optional:nacos:${spring.application.name}.yml?refreshEnabled=true
      - optional:nacos:${spring.application.name}-${spring.profiles.active}.yml?refreshEnabled=true
  cloud:
    nacos:
      server-addr: ${spring.config.nacos.server-addr}
      username: ${spring.config.nacos.username}
      password: ${spring.config.nacos.password}
      config:
        namespace: ${spring.config.nacos.namespace}
        group: DEFAULT_GROUP
      discovery:
        namespace: ${spring.config.nacos.namespace}

---
spring:
  config:
    activate:
      on-profile: local
    nacos:                    # 项目自定义占位属性，供上方连接配置引用
      server-addr: ${NACOS_SERVER_ADDR:127.0.0.1:28848}
      namespace: ${NACOS_NAMESPACE}
      username: ${NACOS_USERNAME}
      password: ${NACOS_PASSWORD}
  datasource:
    url: ${LOCAL_DATASOURCE_URL}
    username: ${LOCAL_DATASOURCE_USERNAME}
    password: ${LOCAL_DATASOURCE_PASSWORD}
  data:
    redis:
      host: ${LOCAL_REDIS_HOST:127.0.0.1}
      port: ${LOCAL_REDIS_PORT:26379}

---
spring:
  config:
    activate:
      on-profile: docker
    nacos:
      server-addr: ${NACOS_SERVER_ADDR:nacos:8848}
  datasource:
    url: ${DOCKER_DATASOURCE_URL}
  data:
    redis:
      host: redis
      port: 6379

---
spring:
  config:
    activate:
      on-profile: dev | stg | pet | prd
    # 共享环境依赖这些配置，不沿用 optional 的本地容错策略。
    # profile 文档中的列表替换公共列表，不是在末尾自动追加。
    import:
      - nacos:${spring.application.name}.yml?refreshEnabled=true
      - nacos:${spring.application.name}-${spring.profiles.active}.yml?refreshEnabled=true
    nacos:
      server-addr: ${NACOS_SERVER_ADDR}
      namespace: ${NACOS_NAMESPACE}
      username: ${NACOS_USERNAME}
      password: ${NACOS_PASSWORD}
```

### Nacos 中的两个 Data ID

以下是同一 namespace 与 Group 下的两个独立配置文件。第一份维护应用共同参数，第二份维护所选环境差异；不要把两份内容作为同一个 Data ID 原样发布。

```yaml
# Data ID: order-service.yml，Group: DEFAULT_GROUP
spring:
  datasource:
    type: com.alibaba.druid.pool.DruidDataSource
    druid:
      max-active: 10           # 示例池容量，按数据库和实例总数评估
order:
  review:
    enabled: false           # 示例业务属性，需由业务代码显式读取
```

```yaml
# Data ID: order-service-prd.yml，Group: DEFAULT_GROUP
spring:
  datasource:
    url: ${DATASOURCE_URL}
    username: ${DATASOURCE_USERNAME}
    password: ${DATASOURCE_PASSWORD}
  data:
    redis:
      host: ${REDIS_HOST}
      port: ${REDIS_PORT:6379}
      password: ${REDIS_PASSWORD}
  security:
    oauth2:
      resourceserver:
        jwt:
          jwk-set-uri: ${APPLICATION_GATEWAY_JWK_SET_URI}
# 仅在当前服务使用 System 等平台客户端时保留，按所用组件选择。
macula:
  cloud:
    endpoint: ${MACULA_CLOUD_ENDPOINT}
    app-key: ${MACULA_CLOUD_APP_KEY}
    secret-key: ${MACULA_CLOUD_APP_SECRET}
order:
  review:
    enabled: true
```

必需导入只表示不将相应加载失败作为可选配置忽略；客户端断连、缓存与恢复行为仍需按实际版本验证。

Data ID 中的占位符在应用解析时仍需有值来源；把 `${DATASOURCE_PASSWORD}` 写进 Nacos 不会自动生成或保管密码。部署环境需注入相应变量，或使用经过验证的密钥集成方案。

## 关键配置与环境选择

| 项目 | 规约 |
| --- | --- |
| `spring.application.name` | 与注册发现、Feign、路由和 Data ID 命名一致，不能被共享配置意外改写 |
| profile | 通过部署明确选择；`local`、`docker`、`dev/stg/pet/prd` 的含义在项目内保持一致 |
| `spring.config.import` | 当前 Nacos 接入使用显式导入，不依赖旧 `bootstrap.yml` 或自动拼接加载规则 |
| namespace / Group / Data ID | 三者一起确定配置；环境隔离使用真实 namespace ID，不能只靠文件名区分生产权限 |
| `optional:nacos:` | 容许相应配置缺失的策略，不能理解为所有 Nacos 依赖都可离线运行 |
| `refreshEnabled` | 决定相应远端配置是否监听变化，不保证任意对象、连接池和客户端自动重建 |
| `spring.config.nacos.*` | 示例工程的自定义占位属性，真正传给组件的是 `spring.cloud.nacos.*` |

推荐使用同一个制品在不同环境部署，通过 `SPRING_PROFILES_ACTIVE=prd` 或本例 `APP_PROFILE=prd` 选择环境。Samples 现有 `@profile.active@` 来自 Maven 资源过滤，`-Pprd` 是构建选择；`--spring.profiles.active=prd` 是运行选择，二者不应被混为同一机制。采用运行时选择的示例无需复制 Maven 占位符。

本例 Data ID 以单个业务环境名拼接；同时激活多个独立 profile 时，不能把逗号分隔的列表直接当成环境文件名。应显式声明导入项，或使用单独、受校验的配置环境变量。

## 加载与覆盖

{{< process-diagram name="configuration-loading" title="配置加载时序：部署选择、仓库导入、Nacos、Bean 绑定和运行变更" >}}

按以下顺序理解本章示例的配置加载：

1. 部署确定 profile、配置中心入口与凭据。
2. 激活的 YAML 文档声明要导入的 Data ID。
3. 导入内容可覆盖发起导入的文档；同一导入列表后项优先，环境 Data ID 可覆盖公共 Data ID。
4. 合并属性源后绑定 Bean；多文档仍要结合文档顺序和 profile 判断。

不能据此推断“本地永远覆盖远端”或“配置中心永远最高”。

常规部署中，命令行参数、JVM 系统属性和进程环境变量还可能覆盖文件及导入数据；测试属性等另有优先级。发现值不符合预期时，按最终 PropertySource 和生效 profile 排查，不凭控制台截图判断。完整顺序参见 [Spring Boot 外部化配置](https://docs.spring.io/spring-boot/4.0/reference/features/external-config.html)。

同一位置统一采用一种文件格式，避免 `.properties` 与 YAML 对同一键重复定义。排查配置时只在受控诊断通道查看来源，保持脱敏，不公开暴露 Actuator 的敏感配置端点。

## 动态刷新与启动配置

| 分类 | 处理方式 |
| --- | --- |
| 业务开关、阈值 | 明确读取路径、可刷新对象和校验策略，验证运行中确实改变行为 |
| 端口、应用名、profile、配置导入与注册身份 | 视为启动配置，通过受控重启发布 |
| 数据源、Redis、消息客户端与线程池结构 | 默认按需要重建或重启处理，不能假定更新配置就安全切换 |
| 密钥、签名材料与身份端点 | 设计轮换和兼容窗口，验证缓存及在途请求 |

业务参数优先通过有类型的 `@ConfigurationProperties` 组织并校验。是否重绑定、是否使用 `@RefreshScope` 或组件专用更新接口，要按 Bean 生命周期与当前依赖实现选择；仅增加注解不能证明底层资源完成切换。

多个关联参数应作为同一个变更单元校验，避免部分生效。发布前说明默认值、允许范围、失败行为和是否重启；更改配置不能替代发布所需的业务测试。

## 地址、凭据与 .env

必须区分浏览器、本机 JVM 和容器各自可达的地址。Gateway 的 IAM 内省、BFF 的 Cloud endpoint、非网关服务的应用 Gateway JWK 分别配置；连接池类型、Redis 前缀按实际绑定代码核对，不能机械替换。

Compose、Vite 和 Java 的环境来源不同：`deploy/.env` 可被项目脚本、Compose 与 Vite 读取，Java/IDE 不会自动加载它。进入前端的配置对浏览器可见，不能存放服务端应用密钥。Gateway 的 System Redis 与业务 Redis 也要区分实例、数据库和凭据。

## 配置发布与验收

配置发布按以下步骤执行：

1. **登记**：记录应用版本、环境、namespace、Group、Data ID、修改前后值、负责人和回退值。
2. **验证**：先在验证环境检查绑定结果与实际业务行为。
3. **发布**：按参数类型执行刷新或受控重启，再逐步扩大范围。
4. **回退**：恢复旧值后，重新验证刷新 / 重启结果；配置中心历史版本仅是回退材料。

本例可在测试应用中绑定 `order.review.enabled`，分别验证默认值、环境覆盖、启动参数覆盖、非法值拒绝，以及运行中更改后的实际业务行为。重启类参数另行验证重启与回滚。不能仅以 Nacos“发布成功”或日志“收到变更”作为验收。

详细接入限制参见 [Nacos 2025.x 配置指南](https://sca.aliyun.com/docs/2025.x/user-guide/nacos/advanced-guide/)，具体 Samples 值见[示例配置](/docs/latest/04_devmanual/模块说明/#示例配置)。
