## 工具与平台

| 项目 | 用途 |
| --- | --- |
| Java 17、Maven | 编译后端，版本与 Macula Boot Parent 保持一致 |
| Node.js 22、npm | 当前 Samples Admin 的 Dockerfile 使用 Node 22；按 package-lock.json 安装依赖 |
| Docker Compose v2 | 启动本地中间件或完整应用容器 |
| Macula Cloud | 提供登录、菜单、用户与权限能力；下一章介绍部署 |

Samples 不重复部署认证中心和系统管理。取得示例源码后，按下一章部署 Macula Cloud，再通过“首次接入”登记 `macula-samples-admin-bff` 应用及管理端使用的 OAuth Client。

## 获取源码

```bash
git clone https://github.com/macula-projects/macula-samples.git
cd macula-samples
```

单个仓库包含后端模块、Admin 前端和部署目录。将根 `pom.xml` 导入 IDE，即可加载全部后端 Maven 模块；Admin 在自己的目录安装前端依赖。

也可以使用 **Macula Boot Archetype** 快速生成自己的单仓项目，自定义组织、项目名和 Java 包名。模板安装、生成命令与参数说明见[快速开始 → 用 Archetype 创建自己的项目](/docs/latest/00_introduce/快速开始/#3-用-archetype-创建自己的项目)。

也支持多仓模式，各模块可在独立仓库中维护，通过工作区统一组织，参考 [macula-samples-workspace](https://cnb.cool/macula-projects/macula-samples-workspace)。本章后续步骤以单仓项目为准。

## 单仓项目结构

Macula Samples 将后端、前端和部署配置放在同一 Git 仓库中。根 `pom.xml` 聚合八个后端模块，`deploy/` 统一维护本地编排；Admin 前端在自身目录构建，不属于 Maven 聚合模块。

```text
macula-samples/
├── pom.xml
├── deploy/
├── macula-samples-parent/
├── macula-samples-api/
├── macula-samples-gateway/
├── macula-samples-admin-bff/
├── macula-samples-service1/
├── macula-samples-basic/
├── macula-samples-openapi/
├── macula-samples-thirdparty/
└── macula-samples-admin/
```

## 应用内的依赖关系

- Parent 统一后端依赖、插件与环境 profile，运行模块继承该 Parent。
- API 聚合 Basic API 和 Service1 API，放置可被其他服务引用的接口契约。
- BFF 依赖 Service1 API，通过 Feign 调用 Service1；业务实现留在 Service1 中。
- Gateway 路由到 BFF / OpenAPI，Admin 通过同源 `/api` 访问 Gateway。
- Basic、Thirdparty 与 OpenAPI 是不同职责的运行模块，按实际业务扩展。

完整说明见[示例模块说明](/docs/latest/04_devmanual/模块说明/)。API 与 Parent 不作为独立的 Spring Boot 服务启动。

## 建立自己的业务项目

以 Samples 作为参考时，先确定应用名、模块职责、API 契约和平台登记信息，再调整包名、构建坐标与配置。应用名需要同时对应服务发现名称、Feign 目标和 Nacos Data ID。

Macula Boot 另提供 [Archetype](https://github.com/macula-projects/macula-boot/tree/main/macula-boot-archetype) 生成项目骨架；本章的模块和配置说明以 Samples 仓库为准，生成后也应逐项核对目标版本的实际文件。

## 本地连接准备

Samples 的默认宿主机端口与 Macula Cloud 分开：MySQL `23306`、Redis `26379`、Nacos `28848`、Samples Gateway `6000`、Samples Admin `5800`。

在 `deploy/.env` 中维护 Compose / Vite 使用的本地环境值。IDE 启动 Java 服务时使用 `local` profile，需覆盖的值在 IDE 环境变量中显式设置，Java 不会自动读取该 `.env` 文件。

认证链路与地址的区别见[示例配置](/docs/latest/04_devmanual/模块说明/#示例配置)，启动步骤见[运行与测试](/docs/latest/04_devmanual/运行与测试/)。

应用与 OAuth Client 的实际登记字段、三个连接方向及认证验收见[首次接入 Macula Cloud](/docs/latest/04_devmanual/首次接入macula-cloud/)。
