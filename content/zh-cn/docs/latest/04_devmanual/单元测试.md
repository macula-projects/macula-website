业务功能写好后，先用单元测试检查规则，再用集成测试检查真实协作。本章介绍两类测试的编写与执行机理；应用启动、前后端联调和整条请求链路的验证见[运行与测试](/docs/latest/04_devmanual/运行与测试/)。

以下约定以当前 Macula Boot Parent 为准。代码中的分层测试与 Redis 测试是**新增测试的教学示例**，不是 Samples 仓库已经提供的测试文件。

## 测试分层

| 类型 | 验证对象 | 推荐方式 | 命名与执行 |
| --- | --- | --- | --- |
| 单元测试 | 参数边界、业务分支、转换、异常与协作调用 | JUnit Jupiter、Mockito，不启动 Spring、不连接外部服务 | `*Test`；`mvn test` |
| 自动配置测试 | 条件装配、属性绑定、用户 Bean 回退 | `ApplicationContextRunner`，只加载所需配置 | `*Test`；`mvn test` |
| 集成测试 | Spring Bean 协作、代理、完整装配，或真实数据库、Redis、消息队列 | `@SpringBootTest` 或明确连接真实依赖的测试 | `*IT`；`mvn verify` |

- 纯逻辑测试直接创建对象；不要为每个测试都加 `@SpringBootTest`。
- Context Runner 虽然创建小型 Spring 容器，本项目将这类隔离的配置测试归在单元测试中。
- 使用完整应用上下文或连接真实外部服务时，归入集成测试，即使测试方法很短。
- Maven 按**类名与插件配置**选择测试，不会根据是否存在 `@SpringBootTest` 自动分类。命名不正确会导致执行阶段错误或漏测。

## 依赖与目录

Samples 的 `macula-samples-parent` 已继承 Macula Boot Parent，并声明测试依赖，业务子模块通常无需重复添加。自建项目尚未引入时，在目标模块的 `pom.xml` 声明：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>
```

JUnit Jupiter、Mockito、AssertJ 和 Spring Test 随测试 Starter 提供，版本交给 Parent 管理。测试代码和资源采用 Maven 标准目录：

```text
macula-samples-service1/
├── src/main/java/                 # 被测业务代码
├── src/test/java/                 # 单元与集成测试均放在这里
│   └── dev/macula/samples/service1/
│       ├── controller/OrderTitleControllerTest.java
│       ├── service/OrderTitleServiceTest.java
│       ├── service/OrderCancelServiceTest.java
│       ├── service/MybatisOrderTitleRepositoryTest.java
│       ├── mapper/OrderTitleMapperIT.java
│       └── redis/RedisAccessIT.java
└── src/test/resources/
    └── application-test.yml       # 测试专用配置
```

默认没有独立的 `src/it/java`。新增测试类后检查实际执行数量；只有 `main` 方法的诊断程序不是 JUnit 用例。

## 示例业务

以下各层共用“按编号读取订单标题”的例子。先定义业务类和数据访问契约，Controller 和 Repository 的示例都以它们为基础。下面两个类型分别放在同名 Java 文件中，均使用 `dev.macula.samples.service1.service` 包：

```java
package dev.macula.samples.service1.service;

import java.util.Optional;

/** 读取订单标题的数据访问边界。 */
public interface OrderTitleRepository {
    Optional<String> findTitle(long orderId);
}
```

```java
package dev.macula.samples.service1.service;

import java.util.NoSuchElementException;

/** 校验订单编号并读取标题。 */
public class OrderTitleService {
    private final OrderTitleRepository repository;

    public OrderTitleService(OrderTitleRepository repository) {
        this.repository = repository;
    }

    public String getTitle(long orderId) {
        if (orderId <= 0) {
            throw new IllegalArgumentException("订单编号必须大于零");
        }
        return repository.findTitle(orderId)
            .orElseThrow(() -> new NoSuchElementException("订单不存在"));
    }
}
```

## 各层测试

常见调用方向为 `Controller → Service → Repository（可选）→ Mapper → 数据库`。Repository 在这里指业务的数据访问封装；使用 MyBatisPlus 的项目可以由 Service 直接调用 Mapper，不必为测试机械补一层。若使用 Spring Data JPA，Repository 接口本身由框架实现，它的数据查询测试也应连接数据库，而不是照搬下面的 Mapper Mock 示例。

| 层次 | 单元测试如何隔离 | 集成测试要补什么 |
| --- | --- | --- |
| Controller | 保留真实 Controller，Mock Service，用 MockMvc 发请求 | 真实 MVC 配置、统一响应 / 异常处理、校验器、安全过滤链和参数扩展 |
| Service | 保留业务类，Mock Repository 或 Mapper、远程客户端 | Spring 代理、事务提交 / 回滚、方法权限及多组件协作 |
| Repository | 保留访问封装，Mock Mapper，检查模型转换、空值和调用参数 | Repository 与真实 Mapper、数据库的协作 |
| Mapper | 不通过 Mock Mapper 证明查询正确 | 真实 SQL、参数绑定、字段映射、分页、租户与逻辑删除插件 |

### Controller：检查 HTTP 契约

Controller 测试主要检查路由、参数绑定、字段校验、状态码和返回结构。本节使用前面的标题查询，新增 `controller/OrderTitleController.java`：

```java
package dev.macula.samples.service1.controller;

import dev.macula.samples.service1.service.OrderTitleService;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RestController;

/** 标题查询的教学 HTTP 入口。 */
@RestController
public class OrderTitleController {
    private final OrderTitleService service;

    public OrderTitleController(OrderTitleService service) {
        this.service = service;
    }

    @GetMapping("/tutorial/orders/{orderId}/title")
    public String getTitle(@PathVariable("orderId") long orderId) {
        return service.getTitle(orderId);
    }
}
```

新增 `src/test/java/dev/macula/samples/service1/controller/OrderTitleControllerTest.java`：

```java
package dev.macula.samples.service1.controller;

import static org.mockito.Mockito.mock;
import static org.mockito.Mockito.verifyNoInteractions;
import static org.mockito.Mockito.when;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

import dev.macula.samples.service1.service.OrderTitleService;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.test.web.servlet.setup.MockMvcBuilders;

/** 隔离 Service，检查路由和请求参数绑定。 */
class OrderTitleControllerTest {
    private OrderTitleService service;
    private MockMvc mvc;

    @BeforeEach
    void setUp() {
        service = mock(OrderTitleService.class);
        mvc = MockMvcBuilders.standaloneSetup(new OrderTitleController(service)).build();
    }

    @Test
    void returnsTitle() throws Exception {
        when(service.getTitle(1001L)).thenReturn("purchase order");

        mvc.perform(get("/tutorial/orders/1001/title"))
            .andExpect(status().isOk())
            .andExpect(content().string("purchase order"));
    }

    @Test
    void rejectsMalformedIdBeforeCallingService() throws Exception {
        mvc.perform(get("/tutorial/orders/not-a-number/title"))
            .andExpect(status().isBadRequest());
        verifyNoInteractions(service);
    }
}
```

这套 `standaloneSetup` 会建立测试用 MVC 基础设施，不启动整个应用。它验证 HTTP 请求绑定，不是直接调用 Java 方法；但没有自动加载 Macula 的实际 Web、安全配置。因此本例断言原始字符串，不断言统一 `Result` 包装。

真实应用的 Controller 还要补以下集成用例，通常命名为 `OrderTitleControllerIT`：

- 通过实际 Web 上下文创建 MockMvc，保留统一响应、异常 Advice、校验器、Security 过滤链和自定义参数解析器；Service 可以按边界替换为测试 Bean。
- 分别验证合法请求、非法表单、业务异常，以及统一错误码。JSON 接口还应断言字段和敏感字段不被返回。
- 验证未认证、缺少操作权限、资源凭证错误和合法请求；请求被拒后断言 Service 未被调用。`@Passkey` 用例须保留实际参数校验扩展，不能只往请求头塞一个字符串。
- MockMvc 接入 Spring Security 需要实际过滤链，并使用 `springSecurity()` 等测试支持。需要时添加 `spring-security-test` 的 test 依赖，版本由 Parent 管理。测试 JWT 的便捷工具提供的是模拟认证，不证明真实签名与 JWK 验签链路通过。
- 保留实际 CSRF 策略，区分 CSRF 拒绝与权限拒绝；不要通过关闭过滤器来让安全用例变绿。期望的 HTTP 状态与错误码以应用配置为准。

Spring Boot 4 的 Web MVC 测试切片支持已拆分模块，使用 `@WebMvcTest` 时按目标 Boot 版本引入对应的 `spring-boot-starter-webmvc-test`，不要直接复制旧版测试包名。上面的独立 MockMvc 示例使用 Samples 已有的 MVC 依赖和通用测试 Starter。

### Service：检查业务分支和副作用

Service 测试直接运行真实业务类，用 Mock 隔离数据访问与外部协作。下面分别示范查询和写操作。

#### 查询：正常、非法输入与不存在

`OrderTitleServiceTest.java` 用 Mock 替代数据访问，只验证这层业务规则：

```java
package dev.macula.samples.service1.service;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertThrows;
import static org.mockito.Mockito.verify;
import static org.mockito.Mockito.verifyNoInteractions;
import static org.mockito.Mockito.when;

import java.util.NoSuchElementException;
import java.util.Optional;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.ExtendWith;
import org.mockito.InjectMocks;
import org.mockito.Mock;
import org.mockito.junit.jupiter.MockitoExtension;

/** 订单标题查询的成功、缺失与非法输入测试。 */
@ExtendWith(MockitoExtension.class)
class OrderTitleServiceTest {
    @Mock
    private OrderTitleRepository repository;

    @InjectMocks
    private OrderTitleService service;

    @Test
    void returnsTitleWhenOrderExists() {
        when(repository.findTitle(1001L)).thenReturn(Optional.of("采购订单"));

        assertEquals("采购订单", service.getTitle(1001L));
        verify(repository).findTitle(1001L);
    }

    @Test
    void rejectsInvalidIdBeforeReadingRepository() {
        assertThrows(IllegalArgumentException.class, () -> service.getTitle(0L));
        verifyNoInteractions(repository);
    }

    @Test
    void rejectsMissingOrder() {
        when(repository.findTitle(1002L)).thenReturn(Optional.empty());

        assertThrows(NoSuchElementException.class, () -> service.getTitle(1002L));
    }
}
```

一次用例分三步：准备输入和协作返回值 → 调用被测方法 → 断言结果、异常或关键副作用。`MockitoExtension` 在每个用例执行前初始化 Mock，`@InjectMocks` 将它交给被测对象；整个过程不启动 Spring，也不访问数据库。

这个测试能证明非法编号在数据访问前被拒绝，不能证明真实 SQL、事务或权限注解生效。直接创建的对象没有经过 Spring 代理，`@Transactional`、`@PreAuthorize` 等行为需要通过容器中的 Bean 另做集成验证。示例省略版权头等工程排版要求，提交框架测试时仍遵守[贡献规范](/docs/latest/11_about/贡献规范/)。

#### 写操作：拒绝后不能继续写入

查询断言之外，写操作还应检查关键副作用。下面新增独立教学类 `service/OrderCancelService.java`，只允许取消草稿订单：

```java
package dev.macula.samples.service1.service;

/** 演示状态检查必须先于持久化写入。 */
public class OrderCancelService {
    /** 本例涉及的订单状态。 */
    public enum Status { DRAFT, COMPLETED }

    /** 取消订单所需的数据访问契约。 */
    public interface Repository {
        Status findStatus(long orderId);
        void markCancelled(long orderId);
    }

    private final Repository repository;

    public OrderCancelService(Repository repository) {
        this.repository = repository;
    }

    public void cancel(long orderId) {
        if (repository.findStatus(orderId) != Status.DRAFT) {
            throw new IllegalStateException("只有草稿订单可以取消");
        }
        repository.markCancelled(orderId);
    }
}
```

在同名测试包新增 `OrderCancelServiceTest.java`，让真实 Service 执行业务逻辑，Mock 它的数据访问契约：

```java
package dev.macula.samples.service1.service;

import static org.junit.jupiter.api.Assertions.assertThrows;
import static org.mockito.Mockito.inOrder;
import static org.mockito.Mockito.mock;
import static org.mockito.Mockito.never;
import static org.mockito.Mockito.verify;
import static org.mockito.Mockito.when;

import org.junit.jupiter.api.Test;
import org.mockito.InOrder;

/** 验证取消订单的成功与拒绝路径。 */
class OrderCancelServiceTest {
    @Test
    void checksStateBeforeCancellingDraft() {
        OrderCancelService.Repository repository = mock(OrderCancelService.Repository.class);
        when(repository.findStatus(1001L)).thenReturn(OrderCancelService.Status.DRAFT);
        OrderCancelService service = new OrderCancelService(repository);

        service.cancel(1001L);

        InOrder calls = inOrder(repository);
        calls.verify(repository).findStatus(1001L);
        calls.verify(repository).markCancelled(1001L);
    }

    @Test
    void rejectsCompletedOrderWithoutWriting() {
        OrderCancelService.Repository repository = mock(OrderCancelService.Repository.class);
        when(repository.findStatus(1002L)).thenReturn(OrderCancelService.Status.COMPLETED);
        OrderCancelService service = new OrderCancelService(repository);

        assertThrows(IllegalStateException.class, () -> service.cancel(1002L));
        verify(repository, never()).markCancelled(1002L);
    }
}
```

第一个用例检查“先查状态，再写入”的业务顺序；第二个用例同时断言抛出异常和没有调用写入。若还有消息发送等协作，也应验证拒绝路径没有调用它们，而不只检查异常类型。

这里验证的是单线程业务顺序，尚未解决查询后状态被其他请求修改的问题。真实取消操作还需用条件更新 / 乐观锁等方式约束并发，并在集成测试中检查影响行数、真实事务回滚和消息一致性，不能把 Mockito 的调用顺序当作数据库原子性证明。


对于创建、修改等操作，至少按业务语义覆盖：

1. 正常路径：参数、状态符合要求，调用正确的数据访问接口并返回结果。
2. 失败路径：记录不存在、状态不允许、当前身份不具备数据权限，拒绝后没有写库或发消息。
3. 边界与重复：空列表、重复请求、并发状态变更等，按业务不变量设计断言。
4. 外部协作：远程超时、缓存缺失或消息发送失败，检查实际约定的降级、补偿或错误传播。

Mock 应位于被测业务类的协作边界，不要把被测 Service 自己 Mock 掉后断言预设返回值。Service 直接依赖 Mapper 时，就 Mock Mapper；依赖 Repository 时，就 Mock Repository，不需要让测试一直穿到数据库。

事务和方法权限属于另一组集成用例：从 Spring 容器取得代理 Bean，用真实数据检查“写入后发生异常是否回滚”；配置实际方法授权，检查缺少角色是否在业务执行前被拒。只给普通单元测试加 `@Transactional`，或给手工创建的对象放入一个模拟身份，都不能证明这些代理机制生效。

### Repository：检查数据访问封装

延续前面的 `OrderTitleRepository`，如果项目通过 Mapper 实现它，可以新增 `service/MybatisOrderTitleRepository.java`：

```java
package dev.macula.samples.service1.service;

import java.util.Optional;
import dev.macula.samples.service1.mapper.OrderTitleMapper;

/** 将 Mapper 的空值语义适配为业务数据访问契约。 */
public class MybatisOrderTitleRepository implements OrderTitleRepository {
    private final OrderTitleMapper mapper;

    public MybatisOrderTitleRepository(OrderTitleMapper mapper) {
        this.mapper = mapper;
    }

    @Override
    public Optional<String> findTitle(long orderId) {
        return Optional.ofNullable(mapper.findTitle(orderId));
    }
}
```

此处是最小实现，没有自动登记为 Spring Bean。需要接入实际应用时，通过 `@Repository` 或显式 `@Bean` 装配，再注入 Service。若封装返回持久化 Entity，应在这一边界按契约转换为内部业务模型，避免把数据库类型扩散到上层。

`MybatisOrderTitleRepositoryTest.java` 放在测试代码的同名业务包：

```java
package dev.macula.samples.service1.service;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertTrue;
import static org.mockito.Mockito.mock;
import static org.mockito.Mockito.verify;
import static org.mockito.Mockito.when;

import dev.macula.samples.service1.mapper.OrderTitleMapper;
import org.junit.jupiter.api.Test;

/** 验证数据访问封装的返回值与参数传递。 */
class MybatisOrderTitleRepositoryTest {
    @Test
    void wrapsReturnedTitle() {
        OrderTitleMapper mapper = mock(OrderTitleMapper.class);
        when(mapper.findTitle(1001L)).thenReturn("采购订单");
        OrderTitleRepository repository = new MybatisOrderTitleRepository(mapper);

        assertEquals("采购订单", repository.findTitle(1001L).orElseThrow());
        verify(mapper).findTitle(1001L);
    }

    @Test
    void representsMissingRowAsEmpty() {
        OrderTitleMapper mapper = mock(OrderTitleMapper.class);
        when(mapper.findTitle(1002L)).thenReturn(null);
        OrderTitleRepository repository = new MybatisOrderTitleRepository(mapper);

        assertTrue(repository.findTitle(1002L).isEmpty());
    }
}
```

这里证明了空值适配和参数传递，SQL 尚未执行。复杂 Repository 还应测试查询条件的组装、模型转换、批量结果与排序语义；薄封装无需把 Mapper 的每个方法机械复制成一份测试。需要验证真正的数据结果时，使用真实 Repository、Mapper 和数据库组合做集成测试。

### Mapper：验证真实 SQL 与映射

新增 `mapper/OrderTitleMapper.java`，作为前面 Repository 示例的协作类型：

```java
package dev.macula.samples.service1.mapper;

import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;
import org.apache.ibatis.annotations.Select;

/** 教学表的标题查询，只演示 SQL 参数绑定。 */
@Mapper
public interface OrderTitleMapper {
    @Select("SELECT title FROM tutorial_order WHERE id = #{orderId}")
    String findTitle(@Param("orderId") long orderId);
}
```

Mock 一个 Mapper 再让它返回预设标题，没有执行 SQL。验证 XML / 注解 SQL、MyBatisPlus CRUD、分页、逻辑删除、租户拦截器时，应连接独立测试数据库并使用真实 Mapper 代理。纯 Java 的转换逻辑仍可另外做单元测试。

下面演示**完整 Service1 上下文**的测试骨架。先在专用测试库中准备业务迁移和教学表，不对共享开发库执行；建表属于环境准备，不放进声称可回滚的 MySQL 测试事务：

```sql
CREATE TABLE tutorial_order (
    id BIGINT PRIMARY KEY,
    title VARCHAR(100) NOT NULL
);
```

新增 `src/test/java/dev/macula/samples/service1/mapper/OrderTitleMapperIT.java`：

```java
package dev.macula.samples.service1.mapper;

import static org.junit.jupiter.api.Assertions.assertNull;

import dev.macula.samples.service1.Service1Application;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.test.context.ActiveProfiles;
import org.springframework.test.context.jdbc.Sql;
import org.springframework.transaction.annotation.Transactional;

/** 在独立测试库验证真实 Mapper 查询。 */
@SpringBootTest(
    classes = Service1Application.class,
    webEnvironment = SpringBootTest.WebEnvironment.NONE,
    properties = {
        "spring.datasource.url=${TEST_JDBC_URL}",
        "spring.datasource.username=${TEST_JDBC_USERNAME}",
        "spring.datasource.password=${TEST_JDBC_PASSWORD}"
    }
)
@ActiveProfiles("local")
@Transactional
class OrderTitleMapperIT {
    @Autowired
    private OrderTitleMapper mapper;

    @Test
    @Sql(statements = {
        "INSERT INTO tutorial_order (id, title) VALUES (910001, 'purchase order')"
    })
    void bindsIdAndMapsTitle() {
        assertEquals("purchase order", mapper.findTitle(910001L));
        assertNull(mapper.findTitle(910002L));
    }
}
```

此例沿用 Samples 的 `local` 配置，**仍可能连接 Nacos、Redis，并运行 Flyway**；设置测试 JDBC 环境变量不会隔离其他组件。执行前准备完整应用所需环境、确认有效配置确实指向专用库，并将这组固定编号留给本用例，不让共享并发用例复用。`@Sql` 的 INSERT 在测试事务中执行，正常结束后由测试事务回滚；教学 DDL 和应用启动时的 Flyway 迁移不在该回滚范围内。

如果只测 Mapper，应改用独立测试配置加载 DataSource、事务管理器、MyBatisPlus 的 SqlSessionFactory、Mapper 扫描及所需插件，像后面的 Redis 示例一样缩小启动范围。不要把手工创建的普通 MyBatis 工厂等同于 Macula 的 MyBatisPlus 装配；原生 `@MybatisTest` 也不会自动证明 Macula 插件已按生产方式加载。

真实业务表按功能增加数据库断言：

- CRUD：插入后主键回填、查询字段、更新影响行数、删除语义及不存在记录。
- SQL：动态查询条件、空条件、联表、排序、分页总数，兼顾重复值和 NULL。
- 数据边界：租户 A 不能读取或修改租户 B 的记录；逻辑删除的数据在适用查询中不可见。
- 插件：版本冲突、自动填充、租户与分页配置都经实际 SQL 生效，不能只断言插件 Bean 存在。

教学表只验证标题查询，没有租户或资源授权语义。测试租户插件时使用真实业务表及其配置，先设置可信测试上下文，结束后恢复 / 清理 Holder 和安全上下文。优先使用与生产一致的数据库类型；H2 通过不代表 MySQL 方言、索引和锁行为已验证。

### 组合验证与执行

先分别验证各层，再保留少量真实链路用例：`HTTP → Controller → Service → Repository / Mapper → 测试数据库`。链路测试检查层间转换、统一响应、事务与权限协作，不能用大量端到端用例替代易定位的业务单元测试。

```bash
# Controller、Service、Repository 的隔离测试
mvn -pl macula-samples-service1 -am test -Plocal \
  '-Dtest=OrderTitleControllerTest,OrderTitleServiceTest,MybatisOrderTitleRepositoryTest,OrderCancelServiceTest' \
  -Dsurefire.failIfNoSpecifiedTests=false

# 数据库与完整应用环境准备好后执行 Mapper 集成测试
mvn -pl macula-samples-service1 -am verify -Plocal \
  -Dit.test=OrderTitleMapperIT -Dfailsafe.failIfNoSpecifiedTests=false
```

Controller 安全测试的框架接入方式见 [Spring Security MockMvc 说明](https://docs.spring.io/spring-security/reference/servlet/test/mockmvc/setup.html)；MyBatis 测试切片的边界见 [MyBatis 测试说明](https://mybatis.org/spring-boot-starter/mybatis-spring-boot-test-autoconfigure/)。

## 编写集成测试

### 明确测试边界

集成测试只加载本次需要协作的组件，先明确：

1. 测试 Spring 装配、真实 Redis，还是完整 Service1 应用？
2. 外部服务的地址、账号和测试数据由谁准备？
3. 测试失败后如何清理本次数据，避免影响其他用例？

下面验证“通过 Spring 注入的模板读写真实 Redis”。Service1 已依赖 Redis Starter，无需额外声明 Redis 客户端。使用独立测试配置和显式 Bean，避免为了检查 Redis 而启动 Nacos、MySQL、IAM 等整套环境。

### 集中测试配置

新增 `src/test/resources/application-test.yml`：

```yaml
spring:
  application:
    name: macula-samples-redis-test
  data:
    redis:
      host: ${TEST_REDIS_HOST:127.0.0.1}
      port: ${TEST_REDIS_PORT}
      database: ${TEST_REDIS_DATABASE:15}
      password: ${TEST_REDIS_PASSWORD:}
```

| 配置 | 用途 |
| --- | --- |
| `TEST_REDIS_PORT` | 必填，明确指定独立测试 Redis，避免误连默认端口 |
| `TEST_REDIS_DATABASE` | 测试逻辑库，默认 15；适用于支持逻辑库的单机 Redis，不代表物理隔离 |
| `TEST_REDIS_PASSWORD` | 从运行环境注入，不将真实密码写入仓库 |

此例在注解中指定 `spring.config.location`，**替换默认配置文件搜索位置**，只读取这份测试配置；不是用测试 profile 叠加完整业务配置。普通应用测试使用 `@ActiveProfiles("test")` 时，仍会加载基础 `application.yml`，其中的 Nacos 导入不会仅因切换 profile 自动消失。

### 编写真实读写用例

新增 `src/test/java/dev/macula/samples/service1/redis/RedisAccessIT.java`：

```java
package dev.macula.samples.service1.redis;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.time.Duration;
import java.util.UUID;
import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.redis.connection.RedisStandaloneConfiguration;
import org.springframework.data.redis.connection.lettuce.LettuceConnectionFactory;
import org.springframework.data.redis.core.StringRedisTemplate;

/** Spring 模板与真实 Redis 的读写集成测试。 */
@SpringBootTest(
    classes = RedisAccessIT.RedisTestConfiguration.class,
    webEnvironment = SpringBootTest.WebEnvironment.NONE,
    properties = "spring.config.location=classpath:/application-test.yml"
)
class RedisAccessIT {
    @Autowired
    private StringRedisTemplate redis;

    private final String key = "macula-test:" + UUID.randomUUID();

    @Test
    void readsBackWrittenValue() {
        redis.opsForValue().set(key, "ready", Duration.ofSeconds(30));

        assertEquals("ready", redis.opsForValue().get(key));
    }

    @AfterEach
    void cleanUp() {
        redis.delete(key);
    }

    /** 仅装配本用例需要的 Redis 连接与模板。 */
    @Configuration(proxyBeanMethods = false)
    static class RedisTestConfiguration {
        @Bean
        LettuceConnectionFactory connectionFactory(
                @Value("${spring.data.redis.host}") String host,
                @Value("${spring.data.redis.port}") int port,
                @Value("${spring.data.redis.database}") int database,
                @Value("${spring.data.redis.password:}") String password) {
            RedisStandaloneConfiguration config =
                new RedisStandaloneConfiguration(host, port);
            config.setDatabase(database);
            if (!password.isEmpty()) {
                config.setPassword(password);
            }
            return new LettuceConnectionFactory(config);
        }

        @Bean
        StringRedisTemplate redisTemplate(LettuceConnectionFactory factory) {
            return new StringRedisTemplate(factory);
        }
    }
}
```

- Spring 创建连接工厂和模板，再注入测试类；断言使用真实 Redis 的返回值，不预设 Mock 结果。
- 唯一 Key 避免不同用例相互覆盖；删除本次 Key，过期时间作为异常退出时的兜底。不要对共享 Redis 执行 `FLUSHDB`。
- 此例验证模板与真实连接，**没有验证 Macula Redis 自动配置发现或完整应用启动**。检查后两者时，要加载真实自动配置或应用入口，并准备其全部依赖。
- 没有 Redis、端口错误或认证失败时，用例应失败并报告环境问题；不能捕获异常后只打印日志，或改成无条件通过。

数据库测试同样准备独立 schema、迁移和最小数据。测试线程内的 Spring 测试事务通常可回滚；经真实 HTTP 请求触发的服务端事务、异步任务、Redis 和消息发送不会随测试方法事务自动回滚，必须安排独立清理。容器化依赖可按项目需要使用 Testcontainers，并明确 Docker 条件和生命周期。

## 测试运行机理

### Maven 如何选择测试

```text
编译主代码与测试代码
        ↓
 test：Surefire → 命名匹配的单元测试
        ↓
 package：生成制品
        ↓
 pre-integration-test：准备环境（需要自行绑定插件或由测试准备）
        ↓
 integration-test：Failsafe → 命名匹配的集成测试，记录结果
        ↓
 post-integration-test：清理环境（需要自行配置）
        ↓
 verify：Failsafe 检查集成测试结果，决定构建是否通过
```

1. Parent 的 Surefire 包含 `Test*`、`*Test`、`*Tests`、`*TestCase`，并排除 `IT*`、`*IT`、`*ITCase`。
2. Failsafe 包含 `IT*`、`*IT`、`*ITCase`，绑定 `integration-test` 和 `verify` 两个目标。
3. 插件把选中的测试交给 JUnit Platform，Jupiter 引擎执行 `@Test` 及前后置回调，断言失败或未处理异常反馈给插件。
4. `mvn test` 到 `test` 阶段结束；`mvn verify` 会先运行单元测试，再运行集成测试。两类源文件都在 `test-compile` 阶段编译，因此集成测试代码编译错误也会使 `mvn test` 失败。
5. Failsafe 将正常用例失败的构建判定延后到 `verify`，让已配置的后置清理阶段有机会执行；不代表任意构建故障都能保证清理。执行到 `verify`，不要只运行 `mvn integration-test`。

Parent 不会自动启动 Redis、数据库或 Macula Cloud。IDE 直接运行类通常也不经过上述 Maven 阶段，IDE 中通过后仍需用 Maven 检查命名、插件和环境是否一致。

### Spring 如何参与

| 方式 | 执行过程与边界 |
| --- | --- |
| 普通 JUnit / Mockito | JUnit 执行生命周期回调和测试方法，Mockito 提供受控协作对象；没有 Spring 容器 |
| Context Runner | 每次 `run` 创建所需的小型上下文，应用属性和用户配置后断言 Bean，结束时关闭上下文 |
| `@SpringBootTest` | 通过 Spring TestContext 与 SpringApplication 创建上下文，注入 Bean 后执行用例；相同配置的上下文可在同一测试进程中复用 |

`@SpringBootTest` 默认不启动真实 HTTP 服务器；`NONE` 不创建 Web 环境，`RANDOM_PORT` 才启动监听随机端口的服务器。上下文缓存不会替你清理数据库、缓存和 Bean 的可变状态；用例须独立，不能依赖执行顺序。

修改 Starter 时，先用 Context Runner 检查默认装配、开关关闭、条件不满足和用户 Bean 覆盖。下面是 Async 已提交测试中的源码节选：

```java
private final ApplicationContextRunner contextRunner = new ApplicationContextRunner()
    .withConfiguration(AutoConfigurations.of(AsyncAutoConfiguration.class));
```

这里显式传入了自动配置类，能验证类内的装配逻辑，不能证明 `AutoConfiguration.imports` 已正确登记。增加少量按正常发现链路启动的 `*IT` 补足这条边界。完整用例见 [AsyncAutoConfigurationTest 源码](https://github.com/macula-projects/macula-boot/blob/5ff9b5c8e6166449ced7512cd3bf74a672aa922e/macula-boot-starters/macula-boot-starter-async/src/test/java/dev/macula/boot/starter/async/config/AsyncAutoConfigurationTest.java)，真实缓存协作可参考 [RedisCacheIT 源码](https://github.com/macula-projects/macula-boot/blob/5ff9b5c8e6166449ced7512cd3bf74a672aa922e/macula-boot-starters/macula-boot-starter-cache/src/test/java/dev/macula/boot/starter/cache/test/RedisCacheIT.java)。

## 运行与定位

在 Samples 单仓根目录执行。先确认所用 Boot Parent 包含上述插件配置；快照可能随本地或远端制品变化，必要时检查目标模块的 `mvn help:effective-pom`。

```bash
# Service1 及所需模块的单元测试
mvn -pl macula-samples-service1 -am test -Plocal

# 指定单个用例；-am 构建的依赖模块可没有同名测试
mvn -pl macula-samples-service1 -am test -Plocal \
  '-Dtest=OrderTitleServiceTest#rejectsInvalidIdBeforeReadingRepository' \
  -Dsurefire.failIfNoSpecifiedTests=false

# 环境准备好后，先设置测试 Redis 端口（按你的实际环境填写）
export TEST_REDIS_PORT=26379

# 先运行单元测试，再执行指定集成测试并检查结果
mvn -pl macula-samples-service1 -am verify -Plocal \
  -Dit.test=RedisAccessIT -Dfailsafe.failIfNoSpecifiedTests=false
```

`-Plocal` 选择 Maven 构建 profile，可能参与业务资源过滤；不等于激活 Spring 的 `test` profile。上面的 Redis 测试通过注解显式选择测试文件。`-Dit.test` 只筛选集成测试，前面的 Surefire 单元测试仍会执行。

| 现象 | 先检查 |
| --- | --- |
| 没有执行用例 | 类名、JUnit 的 `@Test` 导入、目标模块、有效 POM、是否跳过测试；检查测试数量不能只看 BUILD SUCCESS |
| `mvn test` 意外连接外部服务 | 是否把完整上下文 / 外部依赖用例命名为 `*Test` |
| Spring 上下文启动失败 | 找第一个根因，核对测试文件是否仍导入 Nacos、是否加载了不需要的自动配置 |
| Redis / 数据库连接失败 | 实际地址、凭据、端口映射和测试资源；与业务断言失败分开定位 |
| 本地通过、CI 失败 | JDK、Parent 制品、环境变量、基础设施、并行共享数据与 profile 的差别 |

单元报告在各模块 `target/surefire-reports/`，集成报告在 `target/failsafe-reports/`。记录实际命令、测试数量、失败 / 错误 / 跳过数及外部环境；跳过或未运行不能写为验证通过。

关于 Maven 的阶段与结果检查见 [Failsafe 官方说明](https://maven.apache.org/surefire/maven-failsafe-plugin/)；上下文启动方式见 [Spring Boot 测试说明](https://docs.spring.io/spring-boot/reference/testing/spring-boot-applications.html)。
