## 从一个完整调用链开始

当前已提交的 Service1 示例提供应用管理接口，可按以下链路阅读：

`Admin → Gateway → Admin BFF → ApplicationFeignClient → Service1 → Mapper / 数据库`

本页先说明既有链路，再通过[新增工作项业务](#实作新增工作项业务)完成从建表到页面的练习；原有[筛选练习](#实作增加应用编码精确筛选)用于较小范围的契约修改。应用接入与环境字段见[示例配置](/docs/latest/04_devmanual/模块说明/#示例配置)。

## 应用分层规范

本例沿用 `Controller → Service → Mapper`，由 Converter 完成模型转换。下文围绕 API 契约、Service1 实现、BFF 接口和前端筛选逐步修改；各文件的职责见第 2 步的定位表。

分层及对象传递原理见[应用架构](/docs/latest/00_introduce/应用架构/)，必须遵循的边界见[后端开发规范](/docs/latest/03_devrules/后端开发规范/应用分层/)。本例跨服务共享 `*-api` 契约，Entity、Mapper 和 Service 实现留在所属服务内部。

## 1. 先定义服务间契约

在 `macula-samples-api/macula-samples-service1-api` 定义请求表单、查询条件、返回 VO、错误约定和 Feign 接口。现有 `ApplicationFeignClient` 声明 `/api/v1/app` 的分页、创建、更新、删除与维护人相关操作，服务发现目标为 `macula-samples-service1`。

BFF 引用契约制品，不引用 Service1 的实现包。新增字段或接口时同步更新调用方，并核对兼容性。

## 2. 在 Service1 实现业务

| 位置 | 职责 |
| --- | --- |
| controller | 路径、参数接收、表单校验与调用业务服务 |
| service / impl | 业务规则、事务与操作编排 |
| mapper | MyBatis-Plus 数据访问 |
| pojo/entity、pojo/bo | 持久化实体与业务对象 |
| converter | 不同层模型之间的转换 |
| API 模块的 form/query/vo | 对外请求与返回契约 |

对照 `ApplicationController`、`ApplicationServiceImpl`、`ApplicationMapper` 和 `ApplicationConverter` 阅读，保持 HTTP、业务、数据访问的职责边界。业务权限和数据可见性在服务端落实，菜单展示不替代接口校验。

## 3. 管理数据库变更

Service1 已配置 Flyway，当前主线迁移入口是 `src/main/resources/db/migration/V1__baseline.sql`。新增表或字段时按仓库已有序号追加 `V<下一版本>__说明.sql`，不修改已执行迁移。

本地连接地址、账号、数据库名和 Flyway 开关放在模块对应的环境配置中。回归时验证空库初始化和已有库升级两条路径。

## 4. 在 BFF 组织管理端接口

Admin BFF 的 `ApplicationServiceImpl` 注入 `ApplicationFeignClient`，将管理端请求转给 Service1。面向页面的聚合与返回编排留在 BFF，核心业务规则和持久化留在 Service1。

平台用户与菜单通过 BFF 的 System Starter 获取。BFF 配置 Cloud endpoint 和应用凭据；BFF 与 Service1 都配置 Samples Gateway 的 JWK 地址。

## 5. 联调与回归

先运行服务端契约与业务模块的相关测试，再通过 Gateway 与 BFF 联调管理端。验证接口路径、请求 / 返回模型、分页、错误处理、权限与数据库迁移。

构建范围及管理端检查命令见[运行与测试](/docs/latest/04_devmanual/运行与测试/)。Basic、OpenAPI、Thirdparty 的边界见[示例模块说明](/docs/latest/04_devmanual/模块说明/)。

## 实作：新增工作项业务

在现有 Service1 中新增一个“工作项”，完成**建表 → 契约 → Service → BFF → 页面 → 验证**。创建者只能看到自己的工作项，创建与查询还要求平台角色。下列文件由读者在业务分支新建，不是 Samples 已有功能；已有 Application 功能继续保留。

基线为 Samples `5770c37` 与 Boot `a0178da`，使用 Java 17、MyBatis-Plus、MapStruct、Feign 和 Security。先完成首次接入，并在独立开发库中练习；修改前记录工作区状态。API 契约放在 `macula-samples-api/macula-samples-service1-api`，Service 与 BFF 使用现有 Maven 依赖。

### 1. 新增数据库迁移

在 `macula-samples-service1/src/main/resources/db/migration/V2__work_item.sql` 创建表。该基线只有 V1；自己的分支已有后续迁移时，使用下一个未占用版本，不修改已执行的 V1。

```sql
CREATE TABLE work_item (
    id BIGINT NOT NULL AUTO_INCREMENT,
    tenant_id BIGINT NOT NULL,
    owner_username VARCHAR(100) NOT NULL,
    title VARCHAR(120) NOT NULL,
    created_time DATETIME NOT NULL,
    PRIMARY KEY (id),
    KEY idx_work_item_owner (tenant_id, owner_username, id)
);
```

本练习明确采用租户与创建者共同限定数据范围，两个值都取自服务端认证上下文，不能由表单提交。原有 V1 含初始化用的 DROP 语句，不能在已有生产库重新执行。验证迁移时分别准备空开发库和已有 V1 的开发库，均应成功升级且保留原业务数据。

### 3. 实现 Service1 内部各层

`converter/WorkItemConverter.java`：

package dev.macula.samples.service1.converter;

import dev.macula.samples.service1.pojo.entity.WorkItem;
import dev.macula.samples.service1.vo.WorkItemVO;

import org.mapstruct.Mapping;

/** 工作项实体向公开模型的转换。 */

`service/WorkItemService.java`：

```java
package dev.macula.samples.service1.service;

import java.time.LocalDateTime;
import java.util.List;
import com.baomidou.mybatisplus.core.toolkit.Wrappers;
import dev.macula.boot.starter.security.utils.SecurityUtils;
import dev.macula.samples.service1.converter.WorkItemConverter;
import dev.macula.samples.service1.form.WorkItemForm;
import dev.macula.samples.service1.mapper.WorkItemMapper;
import dev.macula.samples.service1.pojo.entity.WorkItem;
import dev.macula.samples.service1.vo.WorkItemVO;
import lombok.RequiredArgsConstructor;
import org.springframework.security.access.AccessDeniedException;
import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

/** 工作项的身份校验、业务规则与事务边界。 */
@Service
@RequiredArgsConstructor
public class WorkItemService {
    private final WorkItemMapper mapper;
    private final WorkItemConverter converter;

    @Transactional
    @PreAuthorize("hasRole('WORK_ITEM_EDITOR')")
    public WorkItemVO create(WorkItemForm form) {
        WorkItem entity = new WorkItem();
        entity.setTenantId(currentTenant());
        entity.setOwnerUsername(currentUser());
        entity.setTitle(form.title().trim());
        entity.setCreatedTime(LocalDateTime.now());
        mapper.insert(entity);
        return converter.toVO(entity);
    }

    @PreAuthorize("hasRole('WORK_ITEM_READER')")
    public List<WorkItemVO> listMine() {
        return mapper.selectList(Wrappers.<WorkItem>lambdaQuery()
                .eq(WorkItem::getTenantId, currentTenant())
                .eq(WorkItem::getOwnerUsername, currentUser())
                .orderByDesc(WorkItem::getId)
                .last("LIMIT 100"))
            .stream().map(converter::toVO).toList();
    }

    private Long currentTenant() {
        Long tenantId = SecurityUtils.getTenantId();
        if (tenantId == null) {
            throw new AccessDeniedException("缺少租户身份");
        }
        return tenantId;
    }

    private String currentUser() {
        String username = SecurityUtils.getCurrentUser();
        if (username == null || username.isBlank()) {
            throw new AccessDeniedException("缺少用户身份");
        }
        return username;
    }
}
```

此处用具体 Service 类组织业务，不要求为每个类机械生成接口；团队需要接口与实现分离时可沿既有 `service/impl` 组织。固定的 `LIMIT 100` 由服务端控制，不拼接请求参数。查询显式限定租户与创建者，不依赖表名恰好命中某个租户插件后缀，也不依赖返回后的归属检查过滤列表。

`controller/WorkItemController.java`：

```java
package dev.macula.samples.service1.controller;

import java.util.List;
import dev.macula.samples.service1.form.WorkItemForm;
import dev.macula.samples.service1.service.WorkItemService;
import dev.macula.samples.service1.vo.WorkItemVO;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/** 工作项 HTTP 入口。 */
@RestController
@RequiredArgsConstructor
@RequestMapping("/api/v1/work-items")
public class WorkItemController {
    private final WorkItemService service;

    @PostMapping
    public WorkItemVO create(@Valid @RequestBody WorkItemForm form) {
        return service.create(form);
    }

    @GetMapping
    public List<WorkItemVO> listMine() {
        return service.listMine();
    }
}
```

Controller 做输入校验，Service 管理规则和事务，Mapper 访问数据，Converter 控制公开字段。读取 `SecurityUtils` 只取得身份，方法角色与查询范围共同决定授权结果。

### 4. 通过 BFF 开放页面接口

在 `macula-samples-admin-bff/src/main/java/dev/macula/samples/admin/bff/controller/WorkItemController.java` 新增：

```java
package dev.macula.samples.admin.bff.controller;

import java.util.List;
import dev.macula.samples.service1.api.WorkItemFeignClient;
import dev.macula.samples.service1.form.WorkItemForm;
import dev.macula.samples.service1.vo.WorkItemVO;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/** 管理端工作项接口；业务数据仍由 Service1 管理。 */
@RestController
@RequiredArgsConstructor
@RequestMapping("/api/v1/work-items")
public class WorkItemController {
    private final WorkItemFeignClient client;

    @PostMapping
    @PreAuthorize("hasRole('WORK_ITEM_EDITOR')")
    public WorkItemVO create(@Valid @RequestBody WorkItemForm form) {
        return client.create(form);
    }

    @GetMapping
    @PreAuthorize("hasRole('WORK_ITEM_READER')")
    public List<WorkItemVO> listMine() {
        return client.listMine();
    }
}
```

这是单一远程调用的最小 BFF；出现聚合、返回转换或复用逻辑时，将编排移入 BFF Service。现有 `AdminBffApplication` 已扫描 `dev.macula.samples.service1` 的 Feign 接口，无需另外复制接口。请求经过现有 `/admin/**` 路由，外部地址为 `/admin/api/v1/work-items`。

### 5. 登记权限并增加页面

在 Cloud 为测试用户分配角色编码 `WORK_ITEM_EDITOR`、`WORK_ITEM_READER`；只读用户仅分配 READER。按实际应用名维护 Gateway 的 GET / POST URL 角色规则，并将页面菜单归属当前业务应用。重新登录取得新 Token 后再验证，旧 Token 或缓存不保证立即包含新增角色。

在 `macula-samples-admin/src/api/model/service1/workItem.js` 创建 API 模块：

```javascript
import config from "@/config"
import http from "@/utils/request"

const url = `${config.API_URL}/${config.MODEL.admin}/api/v1/work-items`
export default {
    list: { get: () => http.get(url) },
    create: { post: data => http.post(url, data) }
}
```

在 `macula-samples-admin/src/views/service1/work-item/index.vue` 创建页面：

```vue
<template>
  <section>
    <el-input v-model="title" maxlength="120" aria-label="工作项标题" />
    <el-button :loading="saving" @click="create">新建工作项</el-button>
    <el-button @click="load">刷新</el-button>
    <p v-if="error" role="alert">{{ error }}</p>
    <el-table :data="rows">
      <el-table-column prop="title" label="标题" />
      <el-table-column prop="ownerUsername" label="创建者" />
    </el-table>
  </section>
</template>

<script>
export default {
  data: () => ({ title: "", rows: [], saving: false, error: "" }),
  mounted() { this.load() },
  methods: {
    async load() {
      this.error = ""
      try {
        const result = await this.$API.service1_workItem.list.get()
        this.rows = result.data || []
      } catch (e) { this.error = e.message || "查询失败" }
    },
    async create() {
      if (!this.title.trim() || this.saving) return
      this.saving = true
      this.error = ""
      try {
        await this.$API.service1_workItem.create.post({ title: this.title })
        this.title = ""
        await this.load()
      } catch (e) { this.error = e.message || "创建失败" }
      finally { this.saving = false }
    }
  }
}
</script>
```

API 自动加载沿用现有 `src/api/index.js`，模块名为 `service1_workItem`。在 Cloud 菜单中按现有动态路由约定登记组件 `service1/work-item/index`，或对照已有 Application 菜单填写；不要把文件路径当作业务接口 URL。示例页面保留服务端拒绝结果，实际产品可按权限隐藏创建按钮，隐藏按钮本身不构成授权。

### 6. 构建、运行与验收

从 Samples 根目录构建契约、Service1 与 BFF，再按[运行与测试](/docs/latest/04_devmanual/运行与测试/)启动：

```bash
mvn -pl macula-samples-service1,macula-samples-admin-bff -am test -Plocal
mvn -pl macula-samples-service1,macula-samples-admin-bff -am package -Plocal -DskipTests
cd macula-samples-admin
npm ci
npm run build
```

确认 Flyway 已成功执行工作项迁移，并用拥有 EDITOR 与 READER 的测试用户登录。在浏览器中新建一条标题为 `first-work-item` 的记录，刷新后应仍可看到；数据库中 tenant_id 与 owner_username 应来自该用户。也可以按首次接入取得外部 Token，经 Gateway 调用：

```bash
read -s ACCESS_TOKEN
curl --fail-with-body 'http://127.0.0.1:6000/admin/api/v1/work-items' \
  -H "Authorization: Bearer ${ACCESS_TOKEN}" \
  -H 'Content-Type: application/json' -d '{"title":"first-work-item"}'
curl --fail-with-body 'http://127.0.0.1:6000/admin/api/v1/work-items' \
  -H "Authorization: Bearer ${ACCESS_TOKEN}"
unset ACCESS_TOKEN
```

| 场景 | 应验证的结果 |
| --- | --- |
| 合法创建与刷新 | 返回公开 VO，ID 为字符串；数据已提交并可再次查询 |
| 空标题或超长标题 | 参数校验失败，没有新增记录 |
| 无 Token / 过期 Token | 请求被拒，没有落库 |
| 只有 READER | 可查询自己的记录，创建被拒 |
| 只有 EDITOR | 可创建，查询仍须单独取得 READER 权限 |
| 同租户另一个用户 | 查询不到原用户的记录 |
| 不同租户身份 | 分别使用有权访问相应租户的测试身份，确认查询不到其他租户记录 |
| 只直连 Service1 | 即使绕过 BFF，Service 的 JWT 与方法授权仍有效 |

自动化测试至少覆盖：Service 规则、非授权身份的拒绝、真实数据库的租户 / 创建者查询条件，以及 API 到 BFF 的契约传递。新增 Java 类型的 Javadoc、格式化和测试规则见[贡献规范](/docs/latest/11_about/贡献规范/)。教程代码的静态检查不等于已完成数据库与认证联调，应记录实际运行的版本、环境和结果。

## 实作：增加应用编码精确筛选

以下是读者在自己分支执行的练习，基于当前 Application 查询链路，新增 `code` 精确筛选，可与原有 `keywords` 同时使用。本网站只提供教程，不修改 Samples 源码，也不声称示例已经运行。

### 1. 修改 API 查询契约

在 `macula-samples-api/macula-samples-service1-api/src/main/java/dev/macula/samples/service1/query/ApplicationPageQuery.java` 中保留原 keywords 字段，新增：

```java
@Schema(description = "应用编码（精确匹配）")
private String code;
```

Lombok `@Data` 生成 getter/setter；参数仍由 Controller 的 `ApplicationPageQuery` 接收。分页接口路径、Feign 签名、返回 VO 均不变，新增条件对旧调用方可选。Entity 与 BO 不需要为同一查询字段重复扩展。

### 2. 修改 Mapper 查询

在 `macula-samples-service1/src/main/resources/mapper/ApplicationMapper.xml` 的 `listApplicationPages` 中，用下面内容替换原 `<where>`；保持原 SELECT、namespace、resultType 不变：

```xml
<where>
    <if test='queryParams.keywords != null and queryParams.keywords.trim() neq ""'>
        AND (application_name LIKE CONCAT('%', #{queryParams.keywords}, '%')
             OR code LIKE CONCAT('%', #{queryParams.keywords}, '%'))
    </if>
    <if test='queryParams.code != null and queryParams.code.trim() neq ""'>
        AND code = #{queryParams.code}
    </if>
</where>
```

原有名称/编码模糊查询的 OR 必须放在同一括号内，再与精确条件 AND；否则可能绕过新增过滤条件。值使用 `#{...}` 绑定，不拼接用户提供的 SQL。

当前 `application` 表已经有 `code` 列，**本练习无需数据库迁移**。实际新增存储字段时，在现有最大版本后追加 Flyway 脚本，同步 Entity、Form、BO/VO 与 Converter；不要为已有列重复加列，也不修改 `V1__baseline.sql`。新增迁移要分别验证空库和旧库。

### 3. 核对 Service 与 BFF 透传

Service1 的 `ApplicationServiceImpl.listApplicationPages` 已把整个 query 传入 `baseMapper.listApplicationPages(page, queryParams)`，再通过 `applicationConverter.bo2Vo` 返回分页；BFF 将同一 Query 传入 `ApplicationFeignClient`。本练习无需新增 Controller 或 Service 方法，但必须让 API、Service1 与 BFF 使用同一份更新后的契约并重启。

新增写入字段时则经 `ApplicationForm → Service → form2Entity → Mapper`，事务留在 Service；跨服务稳定契约放 API，禁止 BFF 直接访问 Service1 数据库。

### 4. 增加前端筛选框

在 `macula-samples-admin/src/views/service1/application/index.vue` 的搜索区新增有名称的输入：

```vue
<el-input v-model="search.code" clearable
          aria-label="应用编码精确筛选" placeholder="应用编码（精确）" />
```

同一文件的 data.search 增加 `code: null`。保留 `upsearch()` 调用 `this.$refs.table.upData(this.search)`，由既有 `$API.service1_application.application.listPages` 请求 `/admin/api/v1/app`，不新增绕过 Gateway 的请求。

### 5. 构建与验收

在 Samples 根目录运行（需准备相关外部依赖）：

```bash
mvn -pl macula-samples-service1,macula-samples-admin-bff -am test
mvn -pl macula-samples-service1,macula-samples-admin-bff -am package -DskipTests
cd macula-samples-admin
npm ci
npm run build
```

按[运行与测试](/docs/latest/04_devmanual/运行与测试/)启动更新后的服务。先按[首次接入](/docs/latest/04_devmanual/首次接入macula-cloud/)取得有效测试用户 Token，再在同一终端调用：

```bash
read -s ACCESS_TOKEN
curl --fail-with-body --get \
  'http://127.0.0.1:6000/admin/api/v1/app' \
  -H "Authorization: Bearer ${ACCESS_TOKEN}" \
  --data-urlencode 'pageNum=1' --data-urlencode 'pageSize=10' \
  --data-urlencode 'code=demo' --data-urlencode 'keywords=demo'
unset ACCESS_TOKEN
```

先通过现有应用创建界面准备 `code=demo` 与另一编码的两条测试数据。期望分页记录只包含编码精确等于 demo 且名称或编码匹配 keywords 的记录；不存在的编码返回空列表，留空 code 保留原有行为。

回归至少覆盖：空条件、精确匹配、不匹配、组合条件以及特殊字符按普通值处理。为 Mapper 增加真实数据库集成测试，验证 SQL 括号与条件组合；Mock Mapper 不能证明 SQL 正确。前端检查清空条件后能恢复列表，无 Token/过期 Token 的拒绝另行验证。上述命令是执行指引，不能将文档构建结果当作业务联调结果。

## 定制与扩展

业务功能在自己的 API、BFF、Service 与前端实现；下面进一步说明怎样调整框架行为。按“配置 → 公开扩展点 / 条件 Bean → 框架源码”的顺序选择，不必为修改一个默认值先 fork 整个 Boot。

| 需要改变什么 | 优先方式 | 例子与验证入口 |
| --- | --- | --- |
| 地址、超时、开关和已开放策略 | 使用组件属性 | Feign 单客户端超时、Cache TTL；启动后确认实际生效值与行为 |
| 默认 Bean 的实现 | 核对条件装配后提供替代 Bean | `@ConditionalOnMissingBean` 可能按类型或名称判断，必须匹配实际条件 |
| 已设计的行为插入点 | 实现公开接口并注册 | Gateway CryptoService / JwtClaimsCustomizer、MapStruct 字段映射 |
| 没有扩展点的框架行为或缺陷 | 修改目标模块并维护兼容性 | 同步配置、README、测试及下游升级验证，按贡献规范提交 |

### 用配置调整行为

以 Feign 超时为例，先在业务应用配置 `spring.cloud.openfeign.client.config.<客户端>.connectTimeout/readTimeout`，按组件页确认单位。分别验证正常响应、超过超时预算的响应，以及非幂等调用的重试行为。配置进入 Nacos 后还需确认客户端是否支持运行时刷新，发布到控制台不等于所有实例已生效。

配置的归属与覆盖规则统一见[环境与配置](/docs/latest/03_devrules/后端开发规范/环境与配置/)，不要在每个业务模块再复制一套不同优先级说明。

### 实现 Gateway 扩展接口

例如，为本应用签发的内部 JWT 附加业务域标识。在 Samples 网关新增 `src/main/java/dev/macula/samples/gateway/config/BusinessJwtConfiguration.java`，生成项目则使用自己网关的扫描包。`JwtClaimsCustomizer` 是 Gateway 的公开扩展点，默认 Bean 使用按类型的缺失条件，因此业务 Bean 可取代默认的空实现。

```java
package dev.macula.samples.gateway.config;

import dev.macula.boot.starter.cloud.gateway.security.JwtClaimsCustomizer;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/** 为内部 JWT 补充应用固定的业务域标识。 */
@Configuration(proxyBeanMethods = false)
public class BusinessJwtConfiguration {
    @Bean
    public JwtClaimsCustomizer businessJwtClaimsCustomizer() {
        return claims -> claims.claim("business_domain", "work-items");
    }
}
```

测试时使用新测试身份或新 Token，避免只命中旧 JWT 缓存；调用网关并在下游**验签后的** JWT / 认证上下文确认 `business_domain`。同时回归原有身份、角色、租户与有效期，不能为方便读取而取消签名校验。固定业务域标识不是角色授权，不从前端请求任意复制可信声明，也不覆盖标准身份字段。

CryptoService 的实现与密钥接入见 [Gateway](/docs/latest/01_services/微服务/gateway/#接口加解密与签名)。方法授权与资源控制见 [Security](/docs/latest/01_services/框架基础/security/)，不通过新增匿名路径实现“扩展”。

### 覆盖条件 Bean

覆盖前定位自动配置：先检查生效的应用类型、属性开关和缺失条件，再按实际条件声明 Bean。例如 Web 默认响应 Advice 同时受 Servlet 环境、缺失类型和 `macula.web.response-advice` 控制；Async 的默认 TaskDecorator 则按固定 Bean 名 `maculaContextPropagatingTaskDecorator` 判断。

因此，`@Primary` 只决定多个候选中优先选谁，不保证默认 Bean 不再注册；`spring.main.allow-bean-definition-overriding` 也不是正常扩展的前提。业务配置需要被扫描或显式导入，Bean 名与类型按源码条件决定。

| 检查点 | 验证方法 |
| --- | --- |
| 替代实现确实被选中 | 检查运行上下文中的实际 Bean；在替代实现中验证一次可观察行为 |
| 没有业务 Bean 时仍能启动 | 回归默认配置路径 |
| 条件不满足时不误装配 | 分别验证禁用属性、应用类型和依赖缺失 |
| 扩展没有丢失原能力 | 例如替换 TaskDecorator 后验证 Trace、MDC、租户和灰度上下文，不能只看异步方法执行成功 |
| 调用者行为兼容 | 回归返回结构、异常、线程模型与公共接口 |

自动配置测试可用 `ApplicationContextRunner` / `WebApplicationContextRunner` 验证条件和回退；依赖真实 Redis、数据库、网关或消息系统的行为再做集成验证。相关分层见[贡献规范](/docs/latest/11_about/贡献规范/#测试分层规范)。

### 确需修改框架源码

先选对维护分支和相关 Starter，记录下游使用的版本。在目标模块阅读 POM、README、自动配置及现有测试，再做最小范围改动；新增或移动自动配置时维护 `AutoConfiguration.imports`，公共行为或配置变化同步更新文档。

在 Boot 仓库验证目标模块及其依赖，例如：

```bash
mvn -pl macula-boot-starters/macula-boot-starter-async -am test
mvn -pl macula-boot-starters/macula-boot-starter-async -am verify
```
