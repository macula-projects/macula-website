## 从一个完整调用链开始

当前已提交的 Service1 示例提供应用管理接口，可按以下链路阅读：

`Admin → Gateway → Admin BFF → ApplicationFeignClient → Service1 → Mapper / 数据库`

本页以该主线代码说明新增业务的方法；应用接入与环境字段见[配置规范](/docs/latest/04_devmanual/应用配置/)。

## 1. 先定义服务间契约

在 `macula-samples-api/macula-samples-service1-api` 定义请求表单、查询条件、返回 VO、错误约定和 Feign 接口。现有 `ApplicationFeignClient` 声明 `/api/v1/app` 的分页、创建、更新、删除与维护人相关操作，服务发现目标为 `macula-samples-service1`。

BFF 引用契约制品，不引用 Service1 的实现包。新增字段或接口时同步更新调用方，并核对兼容性。

## 2. 在 Service1 实现业务

| 位置 | 职责 |
| --- | --- |
| controller | 路径、参数接收、表单校验与调用业务服务 |
| service / impl | 业务规则、事务与操作编排 |
| mapper | MyBatis-Plus 数据访问 |
| pojo/entity、pojo/bo | 持久化实体与业务对象 |
| converter | 不同层模型之间的转换 |
| API 模块的 form/query/vo | 对外请求与返回契约 |

对照 `ApplicationController`、`ApplicationServiceImpl`、`ApplicationMapper` 和 `ApplicationConverter` 阅读，保持 HTTP、业务、数据访问的职责边界。业务权限和数据可见性在服务端落实，菜单展示不替代接口校验。

## 3. 管理数据库变更

Service1 已配置 Flyway，当前主线迁移入口是 `src/main/resources/db/migration/V1__baseline.sql`。新增表或字段时按仓库已有序号追加 `V<下一版本>__说明.sql`，不修改已执行迁移。

本地连接地址、账号、数据库名和 Flyway 开关放在模块对应的环境配置中。回归时验证空库初始化和已有库升级两条路径。

## 4. 在 BFF 组织管理端接口

Admin BFF 的 `ApplicationServiceImpl` 注入 `ApplicationFeignClient`，将管理端请求转给 Service1。面向页面的聚合与返回编排留在 BFF，核心业务规则和持久化留在 Service1。

平台用户与菜单通过 BFF 的 System Starter 获取。BFF 配置 Cloud endpoint 和应用凭据；BFF 与 Service1 都配置 Samples Gateway 的 JWK 地址。

## 5. 联调与回归

先运行服务端契约与业务模块的相关测试，再通过 Gateway 与 BFF 联调管理端。验证接口路径、请求 / 返回模型、分页、错误处理、权限与数据库迁移。

构建范围及管理端检查命令见[运行与测试](/docs/latest/04_devmanual/运行与测试/)。Basic、OpenAPI、Thirdparty 的边界见[模块说明](/docs/latest/04_devmanual/模块说明/)。
