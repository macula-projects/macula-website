一次业务请求如何从前端或外部系统到达最终服务？本章沿着请求流向，说明路由、身份、权限与业务处理分别发生在哪里，以及各环节向下游传递什么。以“用户查询订单”为主线，系统间调用沿用相同的服务链路，但入口凭据与授权依据有所不同。

## 链路总览

![Macula 请求链路：流量入口、网关认证授权、内部 JWT、BFF 聚合、服务调用、业务执行及响应观测](/diagrams/request-chain.svg)

[独立查看链路图](/diagrams/request-chain.svg)，点击图片可放大。图中实线是业务请求，虚线是身份校验、权限和公钥等支撑连接；它表达职责与信息流，不代表所有过滤器的固定执行顺序。

## 流量入口

用户通过 IAM 登录取得外部 Token，再由业务前端携带 Token 访问**应用 Gateway**。外部系统也可使用平台登记的 AK/SK 或 API Key 调用应用入口；这类凭据证明应用身份，不能自动获得登录用户身份与角色。

应用 Gateway 面向业务流量；**Cloud Gateway** 是访问 Macula Cloud 平台服务的入口。浏览器访问业务接口，与 BFF 获取平台菜单、用户信息，是两条用途不同的连接。

<span id="外层认证入口与-url-权限"></span>

## 网关校验

请求进入网关后，要回答两个问题：**谁在调用，是否允许访问这个入口？** Token 通过 IAM 校验；AK/SK 校验应用签名及其允许的 URL 范围；API Key 核对平台中的应用记录。

对 Token 请求，网关结合 System 维护的角色、菜单与接口关系判断 URL 访问权限。匿名放行、仅需认证和未匹配规则时如何处理，由应用的入口策略决定。前端隐藏菜单或按钮只影响交互，请求仍须经过服务端授权。

网关同时承担 HTTP / WebSocket 路由，并可按接口要求执行签名校验、请求解密及响应加密。**入口认证证明调用方身份，接口签名与加解密保护请求内容，二者职责不同。** 这些能力按需启用，协议与开关见 [Gateway Starter](/docs/latest/01_services/微服务/gateway/)。

<span id="中间统一携带网关-jwt"></span>

## 身份转接

入口认证与相应访问规则通过后，网关将可信身份转换为**内部 JWT**，随业务请求转发到目标后端。外部凭据留在入口认证环节，下游通过验证 JWT 识别调用方。JWT 实际携带的角色、scope、租户等声明取决于认证来源，应用凭据不会凭空变成用户权限。

下游 BFF 与业务服务分别从**应用 Gateway 的 JWK 公钥集**获取验签材料，验证内部 JWT，建立各自的 Spring Security 上下文。服务不能仅因请求来自内网或上游已放行，就跳过自己的身份与权限检查。

路由决定请求发往哪个服务；注册发现、负载均衡与灰度能力在启用时参与目标实例选择。身份随调用传递，路由选择本身不授予业务权限。

## 页面聚合

BFF 验证内部 JWT 后，接收面向页面的请求，按需要组合一个或多个业务服务的结果，返回适合前端使用的数据。它也可通过 **Cloud Gateway → System** 获取应用对应的用户、菜单及操作权限。

此处开始执行更具体的业务授权：网关允许访问“订单接口”，不等于当前用户可以执行所有订单操作。BFF 可通过 Security 的方法授权检查具体操作权限；菜单、按钮、URL 和业务方法是同一权限体系中的不同检查点。

BFF 负责页面接口聚合，领域规则、核心业务状态与事务由相应业务 Service 维护。简单业务可按实际需要组合模块，不要求每个应用都部署完整的 BFF 与多服务结构。

## 服务调用

BFF 通过 API 契约调用业务 Service。API 模块描述调用接口与请求、返回模型，是编译依赖的契约制品，不是额外运行的一跳。注册中心帮助定位服务实例，实际业务请求由调用方发到目标服务。

在常见的 Servlet + Feign 调用中，Feign Starter 传递网关生成的 Authorization，以及请求 ID、灰度等必要上下文；目标服务仍需独立验签与授权。异步任务或非 HTTP 调用没有原始请求时，不能假定用户凭据会自动传递，必须明确调用身份与上下文来源。

服务调用还要考虑超时、失败与重试。一次页面请求可能跨越多个服务，但每个服务只维护自己的业务和数据边界；重试不能代替幂等设计，也不能将远程调用视为本地事务的一部分。接入机制见 [Feign](/docs/latest/01_services/微服务/feign/)，工程约束见[微服务规约](/docs/latest/03_devrules/后端开发规范/微服务规约/)。

<span id="内层操作方法与数据归属"></span>

## 业务执行

业务 Service 验证 JWT 后，可通过 `SecurityUtils` 读取当前身份，再结合方法权限、资源归属与业务状态决定能否执行。**读取身份不等于完成授权，通过 BFF 检查也不等于所有服务操作都被授权。**

`@PreAuthorize` 用于执行前的方法授权，`@PostAuthorize` 可根据查询结果做返回后判断，`@CheckOwner` 提供资源归属或资源凭证校验。这些检查与业务查询共同生效：列表、分页、租户和数据范围仍需在查询中限定；执行后检查不能用于阻止已经发生的写入副作用。注解用法、PMS 与 Passkey 配置见 [Security Starter](/docs/latest/01_services/框架基础/security/)。

授权与业务校验通过后，Service 执行领域规则与事务，经 Mapper / Repository 访问自身数据库，按需使用缓存或消息。持久化对象留在服务边界内，接口结果按契约转换后返回；具体对象传递关系见[应用架构 → 模块分层](/docs/latest/00_introduce/应用架构/#模块分层)。

<span id="配套能力"></span>

## 响应观测

处理结果沿 **Service → BFF → Gateway → 调用方** 返回。BFF 组织页面结果；启用接口保护时，网关按协议处理响应加密。任一环节发现身份、权限或业务条件不满足，都可以终止后续调用并返回相应错误。

指标、链路与日志贯穿入口、远程调用和最终服务，用于关联一次请求在哪一跳失败或变慢。业务审计、操作日志记录业务操作事实，与技术链路观测各有用途。异步消息与后台任务是后续独立执行链路，不能假定它们仍处于原 HTTP 请求或同一事务中。

## 连接边界

| 连接 | 解决的问题 |
| --- | --- |
| 应用 Gateway → IAM | 外部 Token 是否有效、属于什么身份 |
| 应用 Gateway → System Redis | 入口权限规则、应用凭据与相关缓存 |
| BFF → Cloud Gateway → System | 平台用户、菜单与操作权限 |
| BFF / Service → 应用 Gateway JWK | 内部 JWT 是否由可信网关签发 |
| BFF → Service → 自有数据 | 本次请求需要执行的业务 |

IAM 校验地址、Cloud 服务入口与应用网关公钥地址不能互换。具体地址和平台登记步骤见[首次接入](/docs/latest/04_devmanual/首次接入macula-cloud/)，本章不展开配置。
